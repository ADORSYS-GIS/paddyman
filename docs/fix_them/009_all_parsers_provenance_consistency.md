# Ticket 009: Ensure Consistent Provenance Metadata Across All Parsers

## Goal

Ensure that every entity generated by the Java, Markdown, and OpenAPI parsers contains a complete and consistent `provenance` block.

## Current Issue

While most entities appear to have provenance information, a full audit is required to guarantee that all required fields are present in every single entity produced by all parsers. Inconsistent or missing provenance data undermines the traceability of the graph.

## Expected Behavior

Every entity in every parser output file must have a `provenance` object containing, at a minimum, the following fields:
- `parser`: The name of the parser that generated the entity (e.g., `java_parser`, `openapi_parser`).
- `stage`: The processing stage (should match the parser name).
- `path`: The absolute path to the source file from which the entity was extracted.
- `module`: The name of the source module (especially for the Java parser). This may not be applicable to all parsers.

## Required Implementation

1.  **Audit:** Review the codebase for all three parsers (`java_parser`, `markdown_parser`, `openapi_parser`).
2.  **Identify Base Entity:** Locate the base Pydantic model or common function responsible for creating entities.
3.  **Enforce Provenance:** Modify this central location to ensure that the `provenance` object is always created and populated with the required fields for every entity instance.
4.  **Pass Context:** Ensure that the necessary context (source file path, module name, etc.) is passed down through the parsing functions to where the entities are instantiated.
5.  **Handle Nulls:** For fields that may not always be available (e.g., `module` for the OpenAPI parser), ensure they are handled gracefully (e.g., set to `null` or an empty string, as per the data model standard).

## Validation

1.  Regenerate all parser outputs for all three parsers.
2.  Write a script to recursively scan all generated JSON files in `POC/DataSource/parsed_output/`.
3.  The script should check every single object (entity) in every file for the existence and non-emptiness of the `provenance` object and its required fields (`parser`, `stage`, `path`).
4.  The script should report any entity that is missing the `provenance` block or any of its required fields.
5.  Manually spot-check a few files from each parser to confirm the script's findings.

## Acceptance Criteria

- Every entity generated by all three parsers contains a `provenance` object.
- The `provenance` object in every entity contains the `parser`, `stage`, and `path` fields.
- The `module` field is present in the `provenance` object for all entities where it is applicable (i.e., from the Java parser).
- The provenance data is accurate and correctly reflects the origin of the entity.

## Testing Requirements

- No new parser tests are required if the fix is implemented in a central, shared location.
- The validation script is the primary means of testing this change.

## Documentation Updates

- None required.

## Completion Criteria

- The validation script runs successfully across all regenerated parser outputs and finds zero issues.
- All acceptance criteria are met.
- No regressions are introduced.

## Implementation Loop

1.  Implement the changes.
2.  Regenerate all parser outputs.
3.  Run the validation script to check for completeness.
4.  If the script finds issues, identify the root cause in the parser and fix it.
5.  Repeat until the validation script passes without errors.
